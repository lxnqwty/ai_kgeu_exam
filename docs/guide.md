# Часть 1. Основы (начальная теория)

## 1. Что такое ИИ, ML и Deep Learning

Эти три понятия вложены друг в друга:

```
┌───────────────────────────────────────────┐
│ Искусственный интеллект (ИИ)              │
│  ┌─────────────────────────────────────┐  │
│  │ Машинное обучение (ML)              │  │
│  │  ┌───────────────────────────────┐  │  │
│  │  │ Глубокое обучение (Deep       │  │  │
│  │  │ Learning, нейронные сети)     │  │  │
│  │  └───────────────────────────────┘  │  │
│  └─────────────────────────────────────┘  │
└───────────────────────────────────────────┘
```

- **Искусственный интеллект (ИИ, AI)** — любые методы, которые позволяют компьютеру решать задачи, обычно требующие человеческого интеллекта: распознавать речь, играть в шахматы, переводить тексты.
- **Машинное обучение (ML, Machine Learning)** — часть ИИ. Вместо того чтобы вручную писать правила, мы показываем алгоритму **примеры (данные)**, и он сам находит закономерности.
- **Глубокое обучение (Deep Learning)** — часть ML, где модели строятся из **нейронных сетей** с несколькими слоями.

**Модель** — это математическая функция с настраиваемыми параметрами, которая по входным данным выдаёт предсказание. 

**Обучение** — подбор этих параметров так, чтобы предсказания были как можно точнее.

---

## 2. Данные: признаки и метки

- **Объект (пример, сэмпл)** — одна запись в данных. Например, одна квартира или одна фотография.
- **Признаки (features, `X`)** — характеристики объекта, которые подаются на вход модели. Для квартиры: площадь, этаж, район.
- **Метка (target, label, `y`)** — то, что нужно предсказать. Для квартиры: цена. Для фото: «кошка» или «собака».
- **Датасет (dataset)** — набор объектов с признаками и (обычно) метками.

Пример таблицы с данными:

| Площадь, м² | Этаж | Комнат | **Цена, млн ₽** |
|---|---|---|---|
| 45 | 3 | 2 | 8.5 |
| 70 | 7 | 3 | 14.2 |
| 30 | 1 | 1 | 5.0 |

Первые три столбца — признаки `X`, последний — метка `y`.

В PyTorch данные хранятся в **тензорах** (многомерных массивах чисел). Обычно `X` имеет форму `(N, количество_признаков)`, где `N` — число объектов.

---

## 3. Виды обучения

- **Обучение с учителем (supervised learning)** — у каждого объекта есть правильный ответ `y`. Модель учится предсказывать его. Это основная тема курса: регрессия и классификация.
- **Обучение без учителя (unsupervised learning)** — правильных ответов нет, модель ищет структуру в данных сама (например, группирует похожие объекты — кластеризация).
- **Обучение с подкреплением (reinforcement learning)** — агент действует в среде и получает награду или штраф (игры, роботы).

---

## 4. Виды задач

### Сводная таблица

| Задача | Что предсказываем | Пример |
|---|---|---|
| Регрессия | число | цена, температура |
| Бинарная классификация | 1 из 2 классов | кошка / собака |
| Многоклассовая классификация | 1 из 3+ классов | цифры 0–9 |

### Шпаргалка по выбору функции потерь

| Тип задачи | Примеры | Функция потерь | Оптимизатор |
|---|---|---|---|
| Регрессия | цена квартиры, температура, зарплата | `MSELoss` | SGD |
| Бинарная классификация (2 класса) | кошка или собака | `BCELoss` | SGD |
| Многоклассовая классификация (3+ класса) | цифры 0–9, кошка / собака / птица | `CrossEntropyLoss` | Adam или SGD |

## 5. Нейрон

**Искусственный нейрон** — простейший вычислительный элемент нейронной сети. Он устроен по аналогии с биологическим нейроном: получает сигналы, суммирует их и решает, что передать дальше.

### Что делает нейрон

1. Берёт входные признаки `x₁, x₂, ..., xₙ`.
2. Умножает каждый на свой **вес** `w₁, w₂, ..., wₙ`.
3. Складывает всё и прибавляет **смещение** `b`.
4. Пропускает результат через **функцию активации** `f`.

Формула:

```
z = w₁·x₁ + w₂·x₂ + ... + wₙ·xₙ + b
y = f(z)
```

В векторном виде: `z = X @ w + b`.

### Из чего состоит нейрон

- **Веса (weights, `w`)** — показывают, насколько важен каждый входной признак. Это главные настраиваемые параметры, именно их подбирает обучение.
- **Смещение (bias, `b`)** — число, которое сдвигает результат. Позволяет нейрону срабатывать, даже когда все входы равны нулю.
- **Функция активации (`f`)** — добавляет нелинейность (см. следующий раздел).

### Пример

Нейрон с двумя входами: `w = [0.5, -1.0]`, `b = 0.2`, вход `x = [2, 1]`.

```
z = 0.5·2 + (-1.0)·1 + 0.2 = 0.2
```

Если активация — сигмоида, то `y = sigmoid(0.2) ≈ 0.55`.

---

## 6. Функции активации

Без функции активации нейрон — просто линейная функция, а сколько линейных слоёв ни складывай, получится всё та же линейная функция. **Активация добавляет нелинейность**, благодаря чему сеть может выучивать сложные зависимости.

### Sigmoid (сигмоида)

```
sigmoid(z) = 1 / (1 + e^(-z))
```

- Значения в диапазоне **от 0 до 1**.
- Удобна на выходе в бинарной классификации: результат можно читать как вероятность.
- В PyTorch: `nn.Sigmoid()`.

### ReLU

```
ReLU(z) = max(0, z)
```

- Отрицательные значения обнуляются, положительные остаются как есть: от 0 до z.
- Простая и быстрая, самая популярная активация для **скрытых слоёв**.
- В PyTorch: `nn.ReLU()`.

### Softmax

- Превращает набор чисел в **вероятности, которые в сумме дают 1**.
- Используется в многоклассовой классификации.
- Но в PyTorch перед `CrossEntropyLoss` его добавлять не нужно: он применяется внутри функции потерь.

| Активация | Диапазон | Где применяется |
|---|---|---|
| Sigmoid | (0, 1) | выход бинарной классификации |
| ReLU | [0, +∞) | скрытые слои |
| Softmax | (0, 1), сумма = 1 | выход многоклассовой классификации |

## 7. Как обучается модель

Обучение — это цикл из нескольких шагов, который повторяется много раз.

### Общая схема

```
┌─► 1. Прямой проход: получаем предсказание
│   2. Считаем потери (насколько ошиблись)
│   3. Обратный проход: считаем градиенты
│   4. Шаг оптимизатора: обновляем веса
└── 5. Обнуляем градиенты и повторяем
```

### Основные понятия

- **Функция потерь (loss function)** — число, которое показывает, насколько предсказание далеко от правильного ответа. Чем меньше, тем лучше. Цель обучения — минимизировать потери.
- **Градиент** — показывает, в какую сторону и насколько нужно изменить каждый вес, чтобы потери уменьшились.
- **Обратное распространение ошибки (backpropagation)** — алгоритм, который эффективно вычисляет градиенты для всех весов. В PyTorch: `loss.backward()`.
- **Оптимизатор (optimizer)** — алгоритм, который обновляет веса по градиентам.
  - **SGD** (стохастический градиентный спуск): `w = w - lr · градиент`.
  - **Adam** — более продвинутый вариант, сам подстраивает шаг для каждого веса.
- **Скорость обучения (learning rate, `lr`)** — размер шага обновления. Слишком большой — обучение «прыгает» и расходится, слишком маленький — учится очень медленно.
- **Эпоха (epoch)** — один полный проход по всему датасету.
- **Батч (batch)** — небольшая порция данных, на которой делается один шаг обновления весов.

### Типовой цикл обучения в PyTorch

```python
import torch.nn as nn
import torch.optim as optim

criterion = nn.BCELoss()
optimizer = optim.SGD(model.parameters(), lr=1e-3)

for epoch in range(100):
    y_pred = model(X)            # 1. прямой проход
    loss = criterion(y_pred, y)  # 2. считаем потери

    optimizer.zero_grad()        # 3. обнуляем старые градиенты
    loss.backward()              # 4. обратный проход
    optimizer.step()             # 5. обновляем веса
```

### Функции потерь

- **MSE (Mean Squared Error)** — средний квадрат ошибки, для регрессии:
  `MSE = среднее((y_pred - y)²)`. В PyTorch: `nn.MSELoss()`.
- **BCE (Binary Cross Entropy)** — для бинарной классификации, ожидает вероятности на входе. В PyTorch: `nn.BCELoss()`.
- **CrossEntropyLoss** — для многоклассовой классификации, ожидает «сырые» значения (логиты). В PyTorch: `nn.CrossEntropyLoss()`.

## 8. Переобучение и проверка качества

### Разбиение данных

Данные делят на части, чтобы честно проверить, как модель работает на **новых** примерах:

- **Обучающая выборка (train)** — на ней модель учится.
- **Валидационная выборка (validation)** — на ней подбираем настройки (гиперпараметры).
- **Тестовая выборка (test)** — финальная проверка, модель её никогда не видела.

### Переобучение и недообучение

- **Переобучение (overfitting)** — модель «зазубрила» обучающие данные, на train ошибка маленькая, а на новых данных большая.
- **Недообучение (underfitting)** — модель слишком простая или мало училась, плохо работает и на train, и на test.

```
Ошибка
  │ \                        ← ошибка на test (растёт при переобучении)
  │  \      ______/
  │   \____/
  │    \______________       ← ошибка на train (продолжает падать)
  └──────────────────────► эпохи
```

Как бороться с переобучением: больше данных, более простая модель, ранняя остановка обучения, регуляризация (например, Dropout).

### Параметры и гиперпараметры

- **Параметры** — то, что модель учит сама: веса и смещения.
- **Гиперпараметры** — то, что задаёт человек до обучения: `lr`, число эпох, число слоёв и нейронов, размер батча.

# Часть 2. Средний уровень (MLP и конвейер обучения)

## 9. Слои и полносвязный слой

**Слой (layer)** — группа нейронов, которые работают параллельно: каждый получает одни и те же входы, но у каждого свои веса.

### Типы слоёв по положению

- **Входной слой** — принимает признаки. Вычислений не делает, его размер равен числу признаков.
- **Скрытые слои (hidden layers)** — внутри сети, именно там происходит «обучение представлений».
- **Выходной слой** — выдаёт итоговое предсказание.

### Полносвязный слой (Fully Connected, Dense, Linear)

Слой, где **каждый нейрон соединён со всеми входами** предыдущего слоя.

В PyTorch: `nn.Linear(in_features, out_features)`.

```python
import torch.nn as nn

layer = nn.Linear(2, 3)  # 2 входа -> 3 нейрона
```

Что внутри этого слоя:

- матрица весов `W` формы `(in_features, out_features)`, здесь `2 × 3 = 6` весов;
- вектор смещений `b` длины `out_features`, здесь 3 числа;
- итого `6 + 3 = 9` обучаемых параметров.

Вычисление: `Y = X @ W + b`.

```
Входы        Нейроны слоя
 x₁ ──┬────► [n₁]
      ├────► [n₂]
 x₂ ──┴────► [n₃]
(каждый вход соединён с каждым нейроном)
```

**Формула числа параметров** полносвязного слоя:

```
параметров = in_features × out_features + out_features
```

> Важно: сам по себе `nn.Linear` не содержит активации. Её нужно добавлять отдельным элементом (`nn.ReLU()`, `nn.Sigmoid()`).

> Заметка про PyTorch: внутри `nn.Linear` матрица хранится в транспонированном виде, `layer.weight.shape == (out_features, in_features)`. На результат это не влияет, но пригодится, когда будешь смотреть параметры слоя.

Посмотреть параметры и их число:

```python
for name, p in layer.named_parameters():
    print(name, p.shape)   # weight (3, 2), bias (3,)

total = sum(p.numel() for p in layer.parameters())  # 9
```

## 10. MLP (многослойный перцептрон)

**MLP (Multi-Layer Perceptron)** — нейронная сеть из нескольких **полносвязных слоёв** с функциями активации между ними. Это самая базовая архитектура глубокого обучения.

### Структура

```
Вход → [Linear → ReLU] → [Linear → ReLU] → Linear → (Sigmoid / без активации)
         скрытый слой 1    скрытый слой 2   выходной слой
```

- Данные идут строго в одну сторону: от входа к выходу (**прямое распространение**, forward pass).
- Скрытых слоёв может быть один и более. Чем их больше, тем сеть «глубже».
- Между скрытыми слоями нужна нелинейная активация (обычно ReLU).

### Пример: MLP для бинарной классификации

```python
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(2, 8),   # вход: 2 признака -> 8 нейронов
    nn.ReLU(),
    nn.Linear(8, 4),   # скрытый слой: 8 -> 4
    nn.ReLU(),
    nn.Linear(4, 1),   # выход: 1 число
    nn.Sigmoid()       # вероятность от 0 до 1
)
```

### Пример: MLP для многоклассовой классификации (10 цифр)

```python
model = nn.Sequential(
    nn.Linear(784, 128),  # 28x28 пикселей -> 128 нейронов
    nn.ReLU(),
    nn.Linear(128, 10)    # 10 классов, без Softmax (он внутри CrossEntropyLoss)
)
```

### Как выбирать выход сети

| Задача | Выходной слой | Активация на выходе |
|---|---|---|
| Регрессия | `nn.Linear(..., 1)` | нет |
| Бинарная классификация | `nn.Linear(..., 1)` | `Sigmoid` |
| Многоклассовая классификация | `nn.Linear(..., число_классов)` | нет (Softmax внутри `CrossEntropyLoss`) |

### `nn.Sequential`

Контейнер, который применяет слои **последовательно**, один за другим. Удобен для простых сетей, где данные идут по цепочке.

### Свой класс сети: `nn.Module`

Когда сеть сложнее цепочки, её описывают классом. Результат тот же, но можно управлять `forward` как угодно.

```python
class MLP(nn.Module):
    def __init__(self, in_features, hidden, out_features):
        super().__init__()
        self.fc1 = nn.Linear(in_features, hidden)
        self.fc2 = nn.Linear(hidden, out_features)
        self.relu = nn.ReLU()

    def forward(self, x):
        x = self.relu(self.fc1(x))
        return self.fc2(x)

model = MLP(2, 8, 1)
```

Вызывать надо `model(x)`, а не `model.forward(x)`.

### Сколько слоёв и нейронов брать

Строгого правила нет, это гиперпараметры. Практичный старт: 1–2 скрытых слоя по 16–128 нейронов. Если модель недообучается, увеличиваем сеть. Если переобучается, уменьшаем или добавляем регуляризацию (раздел 14).

## 11. Подготовка данных

Нейросети чувствительны к масштабу признаков. Площадь в диапазоне 30–150 и число комнат 1–4 дают очень разные по величине сигналы, и обучение идёт хуже.

### Масштабирование признаков

- **Стандартизация (z-score)**: `x' = (x − mean) / std`. После неё у признака среднее 0 и разброс 1. Самый частый выбор.
- **Min-Max нормализация**: `x' = (x − min) / (max − min)`. Значения попадают в диапазон [0, 1].

**Важное правило:** `mean` и `std` (или `min` и `max`) считаются **только по обучающей выборке**, а затем применяются к val и test. Иначе информация из тестовых данных «просачивается» в обучение (утечка данных, data leakage).

```python
mean = X_train.mean(dim=0)
std = X_train.std(dim=0)

X_train = (X_train - mean) / std
X_val   = (X_val - mean) / std
X_test  = (X_test - mean) / std
```

### Категориальные признаки

Район «центр / север / юг» нельзя просто записать числами 0, 1, 2: сеть решит, что юг «больше» центра. Используют **one-hot кодирование**:

| Район | центр | север | юг |
|---|---|---|---|
| центр | 1 | 0 | 0 |
| юг | 0 | 0 | 1 |

### Разбиение

Перемешиваем и делим на train / val / test, например 70 / 15 / 15 или 80 / 10 / 10:

```python
N = X.shape[0]
perm = torch.randperm(N)
n_train = int(0.8 * N)

train_idx, test_idx = perm[:n_train], perm[n_train:]
X_train, y_train = X[train_idx], y[train_idx]
X_test,  y_test  = X[test_idx],  y[test_idx]
```

## 12. Батчи, режимы train и eval

Прогонять весь датасет за один шаг неудобно (не хватит памяти, и обновлений весов за эпоху будет мало). Поэтому данные подают **батчами**: в PyTorch их нарезает `DataLoader`, а при `shuffle=True` батчи каждую эпоху разные, и обучение устойчивее (для val и test перемешивание не нужно).

### Цикл обучения с батчами

```python
for epoch in range(50):
    model.train()
    for xb, yb in train_loader:
        y_pred = model(xb)
        loss = criterion(y_pred, yb)

        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
```

Теперь **один шаг оптимизатора = один батч**, а **эпоха = проход по всем батчам**. Число шагов за эпоху: `ceil(N / batch_size)`.

### Режимы `train()` и `eval()` и `torch.no_grad()`

- `model.train()` включает режим обучения (нужен, например, для Dropout).
- `model.eval()` включает режим проверки: Dropout отключается.
- `with torch.no_grad():` не считает градиенты, экономит память и время. Используется при проверке и предсказании.

```python
model.eval()
with torch.no_grad():
    y_pred = model(X_val)
    val_loss = criterion(y_pred, y_val)
```

### Размер батча

Типичные значения: 16, 32, 64, 128. Маленький батч даёт более «шумные» шаги, но чаще обновляет веса. Большой батч стабильнее, но требует больше памяти.

## 13. Метрики качества

Функция потерь нужна для обучения, а **метрика** показывает качество в понятных человеку единицах. Это разные вещи: loss может быть неинтерпретируемым числом, а accuracy сразу понятна.

### Регрессия

- **MAE** (Mean Absolute Error) — средняя абсолютная ошибка: `среднее(|y_pred − y|)`. В тех же единицах, что и `y` (например, «ошибаемся в среднем на 1.2 млн ₽»).
- **RMSE** — корень из MSE. Тоже в единицах `y`, сильнее штрафует большие ошибки.
- **R²** — доля разброса `y`, объяснённая моделью. 1 — идеально, 0 — не лучше, чем предсказывать среднее.

```python
mae = (y_pred - y).abs().mean()
rmse = ((y_pred - y) ** 2).mean().sqrt()
```

### Классификация

Для бинарной классификации модель выдаёт вероятность, и нужен **порог** (обычно 0.5):

```python
preds = (y_pred > 0.5).float()
accuracy = (preds == y).float().mean()
```

Для многоклассовой берём класс с максимальным значением:

```python
preds = y_pred.argmax(dim=1)
accuracy = (preds == y).float().mean()
```

### Матрица ошибок (confusion matrix)

Для бинарной классификации (класс 1 — «положительный», например «спам»):

|  | Предсказали 1 | Предсказали 0 |
|---|---|---|
| **Реально 1** | TP (верно нашли) | FN (пропустили) |
| **Реально 0** | FP (ложная тревога) | TN (верно отвергли) |

- **Accuracy** = `(TP + TN) / все` — доля верных ответов.
- **Precision** = `TP / (TP + FP)` — из того, что назвали положительным, сколько действительно положительные.
- **Recall** = `TP / (TP + FN)` — из реально положительных, сколько нашли.
- **F1** = `2 · Precision · Recall / (Precision + Recall)` — компромисс между precision и recall.

### Когда accuracy обманывает

Если 95% писем не спам, модель «всегда отвечай: не спам» получит accuracy 95%, но спам не найдёт никогда. При **несбалансированных классах** смотрят на precision, recall и F1.

Что важнее — зависит от задачи:

- Диагностика болезни: важен **recall** (лучше перестраховаться, чем пропустить больного).
- Спам-фильтр: важен **precision** (не хочется терять нужные письма).

### Порог можно менять

Если поднять порог с 0.5 до 0.8, precision обычно растёт, а recall падает. И наоборот.

## 14. Регуляризация

**Регуляризация** — приёмы, которые борются с переобучением (см. раздел 8 «Переобучение и проверка качества»).

### Dropout

Во время обучения случайно «выключает» часть нейронов на каждом шаге. Сеть не может опираться на отдельные нейроны и учится устойчивее.

```python
model = nn.Sequential(
    nn.Linear(20, 64),
    nn.ReLU(),
    nn.Dropout(p=0.3),   # выключаем 30% нейронов
    nn.Linear(64, 1),
    nn.Sigmoid()
)
```

- Работает только в режиме `model.train()`. В `model.eval()` отключается автоматически.
- Типичное `p`: 0.1–0.5. Ставят после активации скрытых слоёв, но не перед выходом.

### Weight decay (L2-регуляризация)

Штрафует слишком большие веса, из-за чего модель получается «спокойнее» и меньше подгоняется под шум. В PyTorch задаётся в оптимизаторе:

```python
optimizer = optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-4)
```

### Ранняя остановка (early stopping)

Следим за ошибкой на **validation**. Как только она перестаёт улучшаться несколько эпох подряд, обучение останавливаем и берём лучшую модель.

```python
best_val = float("inf")
patience, wait = 5, 0

for epoch in range(200):
    # ... обучение на train ...
    # ... val_loss на validation ...
    if val_loss < best_val:
        best_val = val_loss
        wait = 0
        torch.save(model.state_dict(), "best.pt")
    else:
        wait += 1
        if wait >= patience:
            break
```

### Другие способы

- **Больше данных** — самое надёжное средство.
- **Проще модель** — меньше слоёв и нейронов.
- **Аугментация данных** — искусственное расширение датасета (например, повороты картинок).

## 15. Оптимизаторы и learning rate

### SGD с моментом

Обычный SGD идёт строго по текущему градиенту и может «топтаться» в узких оврагах функции потерь. **Момент (momentum)** добавляет «инерцию»: шаг учитывает направление прошлых шагов.

```python
optimizer = optim.SGD(model.parameters(), lr=1e-2, momentum=0.9)
```

### Adam

Для каждого веса подстраивает шаг сам, поэтому обычно сходится быстрее и менее чувствителен к выбору `lr`. Хороший вариант «по умолчанию».

```python
optimizer = optim.Adam(model.parameters(), lr=1e-3)
```

### Какой `lr` брать

| Оптимизатор | Типичный `lr` для старта |
|---|---|
| SGD | 1e-2 … 1e-1 (с моментом чаще 1e-2) |
| Adam | 1e-3 (иногда 1e-4) |

### Как понять, что `lr` не тот

- Loss «скачет» или растёт до `nan` → `lr` слишком большой.
- Loss падает, но очень медленно → `lr` слишком маленький.
- Loss уменьшается плавно → всё в порядке.

### Планировщик learning rate (scheduler)

Часто полезно уменьшать `lr` по ходу обучения: сначала большие шаги, затем точная подстройка.

```python
scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=20, gamma=0.5)

for epoch in range(100):
    # ... обучение ...
    scheduler.step()   # раз в эпоху: каждые 20 эпох lr умножается на 0.5
```

## 16. Практика: BCEWithLogitsLoss и чтение кривых обучения

### Про `BCEWithLogitsLoss`

Это функция потерь, у которой `Sigmoid` уже внутри, поэтому сеть заканчивается просто `nn.Linear(..., 1)` без активации. Она численно стабильнее, чем `Sigmoid` + `BCELoss`, и часто используется на практике. В курсе по умолчанию работаем с `Sigmoid` + `BCELoss`.

### Как читать кривые обучения

| Картина | Диагноз | Что делать |
|---|---|---|
| train и val ошибки высокие | недообучение | больше нейронов или слоёв, дольше учить, поднять `lr` |
| train низкая, val высокая и растёт | переобучение | регуляризация, больше данных, ранняя остановка |
| обе низкие и близки | хорошо | можно останавливаться |
| ошибка скачет или `nan` | слишком большой `lr` или плохие данные | уменьшить `lr`, проверить данные |

# Часть 3. Усложнённая теория (внутри обучения и архитектуры)

## 17. Автоградиент и обратное распространение изнутри

### Вычислительный граф

Когда мы выполняем операции над тензорами, PyTorch запоминает, из чего получен каждый результат. Получается **граф вычислений**:

```
w ──┐
    ├─► (w·x) ──┐
x ──┘           ├─► z ──► (z − y) ──► (·)² ──► loss
b ──────────────┘
```

Прямой проход идёт слева направо и считает значения. Обратный проход идёт справа налево и считает градиенты по **правилу цепочки (chain rule)**:

```
dL/dw = dL/dz · dz/dw
```

Каждая операция знает свою локальную производную. Обратное распространение просто перемножает их по пути от `loss` до нужного параметра.

### Пример вручную

Нейрон без активации: `z = w·x + b`, потери `L = (z − y)²`. Пусть `w = 1`, `b = 0`, `x = 2`, `y = 5`.

```
z = 1·2 + 0 = 2
L = (2 − 5)² = 9

dL/dz = 2(z − y) = −6
dL/dw = dL/dz · dz/dw = −6 · x = −12
dL/db = dL/dz · dz/db = −6 · 1  = −6
```

Шаг градиентного спуска с `lr = 0.1`: `w = 1 − 0.1·(−12) = 2.2`, `b = 0 − 0.1·(−6) = 0.6`. Теперь `z = 2.2·2 + 0.6 = 5.0`, то есть ровно то, что нужно.

Проверка в PyTorch:

```python
import torch

w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
x, y = 2.0, 5.0

z = w * x + b
loss = (z - y) ** 2
loss.backward()

print(w.grad, b.grad)   # tensor(-12.) tensor(-6.)
```

### Что важно знать про autograd

- `requires_grad=True` включает отслеживание. Параметры `nn.Module` включают его сами.
- `loss.backward()` **накапливает** градиенты в `.grad`, а не перезаписывает. Поэтому нужен `optimizer.zero_grad()`.
- `with torch.no_grad():` отключает построение графа (проверка, предсказание).
- `tensor.detach()` возвращает тензор, «отрезанный» от графа. Через него градиенты дальше не пойдут.
- После `backward()` граф по умолчанию удаляется. Повторный вызов на том же графе даст ошибку.

### Градиенты в слое

Для слоя `Y = X @ W + b` и потерь `L` с известным `dL/dY` градиенты равны:

```
dL/dW = Xᵀ @ dL/dY
dL/db = сумма dL/dY по батчу
dL/dX = dL/dY @ Wᵀ
```

Последняя строка передаёт градиент в предыдущий слой. Так ошибка «протекает» от выхода к входу.

## 18. Затухающие и взрывающиеся градиенты, инициализация

### Проблема

При обратном проходе градиент умножается на множители каждого слоя. Если они в среднем меньше 1, градиент **затухает** (vanishing gradient), если больше 1, **взрывается** (exploding gradient).

Пример с сигмоидой: её производная не больше `0.25`. Через 10 слоёв градиент уменьшится минимум в `0.25¹⁰ ≈ 10⁻⁶` раз. Ранние слои почти не получают сигнал и не учатся.

| Симптом | Причина | Средства |
|---|---|---|
| Ранние слои не обучаются, loss почти не меняется | затухание | ReLU и его варианты, нормализация, хорошая инициализация, residual-связи |
| Loss скачет до `inf` или `nan` | взрыв | меньше `lr`, gradient clipping (раздел 27), инициализация |

**Dead ReLU.** Если на входе ReLU всегда отрицательные значения, нейрон выдаёт 0 и его градиент равен 0. Такой нейрон «умер» и больше не обучается. Помогают меньший `lr` и варианты ReLU (раздел 19).

### Инициализация весов

Нельзя ставить все веса нулевыми: все нейроны слоя станут одинаковыми и будут обновляться одинаково (симметрия не нарушится). Веса инициализируют случайно, но так, чтобы разброс значений **не рос и не падал** от слоя к слою.

- **Xavier (Glorot)** — для `tanh` и `sigmoid`. Дисперсия весов около `2 / (fan_in + fan_out)`.
- **He (Kaiming)** — для ReLU. Дисперсия весов около `2 / fan_in`.

```python
import torch.nn as nn

layer = nn.Linear(256, 128)
nn.init.kaiming_normal_(layer.weight, nonlinearity="relu")
nn.init.zeros_(layer.bias)

# или для tanh / sigmoid:
nn.init.xavier_uniform_(layer.weight)
```

Инициализация всей модели:

```python
def init_weights(m):
    if isinstance(m, nn.Linear):
        nn.init.kaiming_normal_(m.weight, nonlinearity="relu")
        nn.init.zeros_(m.bias)

model.apply(init_weights)   # применяется ко всем вложенным модулям
```

Смещения обычно инициализируют нулями. Стандартная инициализация `nn.Linear` в PyTorch разумна, и для небольших сетей её часто не меняют.

### Residual-связи (skip connections)

Выход блока складывается с его входом: `y = x + F(x)`. Градиент получает «короткий путь» мимо слоёв, и очень глубокие сети (ResNet, трансформеры) становятся обучаемыми.

```python
class ResidualBlock(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(dim, dim), nn.ReLU(),
            nn.Linear(dim, dim)
        )

    def forward(self, x):
        return torch.relu(x + self.net(x))
```

## 19. Продвинутые функции активации

| Активация | Формула | Особенности |
|---|---|---|
| **Tanh** | `(e^z − e^−z) / (e^z + e^−z)` | диапазон (−1, 1), центрирована в нуле, но тоже затухает |
| **Leaky ReLU** | `z` при `z > 0`, иначе `0.01·z` | не обнуляет отрицательные значения полностью, помогает против dead ReLU |
| **GELU** | примерно `z · Φ(z)` | гладкая, стандарт в трансформерах |
| **SiLU (Swish)** | `z · sigmoid(z)` | гладкая, часто чуть лучше ReLU в глубоких сетях |

```python
nn.Tanh()
nn.LeakyReLU(negative_slope=0.01)
nn.GELU()
nn.SiLU()
```

Практическое правило: начинай с `ReLU`. Если есть проблемы с «мёртвыми» нейронами, пробуй `LeakyReLU`. В трансформерах обычно `GELU`.

## 20. Нормализация внутри сети

В разделе 11 мы нормализовали входные данные. Нормализацию можно делать и **между слоями**, она стабилизирует и ускоряет обучение.

### Batch Normalization

Для каждого признака считаются среднее и дисперсия **по батчу**, затем значения приводятся к стандартному виду и масштабируются обучаемыми параметрами `γ` и `β`:

```
x̂ = (x − μ_batch) / sqrt(σ²_batch + ε)
y = γ · x̂ + β
```

```python
model = nn.Sequential(
    nn.Linear(20, 64),
    nn.BatchNorm1d(64),   # число признаков = число нейронов слоя
    nn.ReLU(),
    nn.Linear(64, 1),
    nn.Sigmoid()
)
```

Важно:

- В режиме `train()` используются статистики текущего батча и параллельно накапливаются «скользящие» статистики.
- В режиме `eval()` используются накопленные статистики. Поэтому **забыть `model.eval()` особенно опасно** для сетей с BatchNorm.
- Плохо работает на очень маленьких батчах (статистика шумная).
- Типичный порядок: `Linear → BatchNorm → активация`.

### Layer Normalization

Нормализует признаки **одного объекта** (а не батч), поэтому не зависит от размера батча и ведёт себя одинаково в `train` и `eval`. Стандарт для трансформеров и рекуррентных сетей.

```python
norm = nn.LayerNorm(64)
```

| | BatchNorm | LayerNorm |
|---|---|---|
| Усредняет по | объектам батча | признакам одного объекта |
| Зависит от размера батча | да | нет |
| Где обычно | CNN, MLP | трансформеры, RNN |

## 21. Продвинутые функции потерь

### Регрессия

- **MAE (L1Loss)** — `среднее(|y_pred − y|)`. Устойчива к выбросам, но градиент не затухает у нуля.
- **Huber (HuberLoss / SmoothL1Loss)** — квадратична при малых ошибках, линейна при больших. Компромисс между MSE и MAE.

```python
nn.L1Loss()
nn.HuberLoss(delta=1.0)
```

### Несбалансированные классы

Если положительных объектов мало, модель выгоднее всегда отвечать «0». Решения:

```python
# бинарная: вес положительного класса, например 1 к 9 -> pos_weight = 9
criterion = nn.BCEWithLogitsLoss(pos_weight=torch.tensor([9.0]))

# многоклассовая: веса классов
weights = torch.tensor([1.0, 3.0, 5.0])
criterion = nn.CrossEntropyLoss(weight=weights)
```

Напоминание: `BCEWithLogitsLoss` содержит `Sigmoid` внутри, поэтому сеть заканчивается на `nn.Linear(..., 1)` без активации.

Кроме весов помогают пересэмплирование (дублировать редкий класс), подбор порога и метрики precision / recall / F1.

### Как устроена CrossEntropyLoss

Для логитов `z` и правильного класса `c`:

```
loss = −log( softmax(z)[c] )
```

Если сеть даёт правильному классу вероятность 0.9, потери `−log(0.9) ≈ 0.105`. Если 0.1, потери `−log(0.1) ≈ 2.3`. Чем увереннее ошибка, тем больше штраф.

## 22. Свёрточные сети (CNN)

### Зачем нужны

Если картинку 28×28 развернуть в вектор из 784 чисел и подать в MLP, теряется структура: сеть не знает, что соседние пиксели связаны. Для картинки 224×224×3 первый слой MLP потребовал бы миллионы параметров.

Свёрточные сети используют две идеи:

- **Локальность** — нейрон смотрит на небольшое окно (например, 3×3), а не на всю картинку.
- **Разделение весов (weight sharing)** — один и тот же фильтр скользит по всему изображению. Объект распознаётся независимо от его положения.

### Свёртка

**Фильтр (ядро, kernel)** — маленькая матрица весов, например 3×3. Он скользит по изображению, в каждой позиции перемножает свои веса с пикселями под ним и суммирует. Получается **карта признаков (feature map)**. Один фильтр ищет один паттерн (границу, угол, пятно).

В PyTorch изображения хранятся в форме `(N, C, H, W)`: батч, каналы, высота, ширина.

```python
conv = nn.Conv2d(in_channels=1, out_channels=16, kernel_size=3, stride=1, padding=1)
```

- `out_channels` — сколько фильтров, то есть сколько карт признаков получится.
- `stride` — шаг скольжения.
- `padding` — сколько нулей добавить по краям (с `padding=1` и ядром 3 размер сохраняется).

**Размер выхода:**

```
H_out = floor( (H + 2·padding − kernel_size) / stride ) + 1
```

Пример: вход 28, ядро 3, `padding=1`, `stride=1` → `(28 + 2 − 3)/1 + 1 = 28`.

**Число параметров:**

```
параметров = out_channels · in_channels · K · K + out_channels
```

Для `Conv2d(1, 16, 3)`: `16·1·3·3 + 16 = 160`. Это не зависит от размера картинки.

### Pooling

Уменьшает размер карты, оставляя важное. **MaxPool** берёт максимум в окне. `nn.MaxPool2d(2)` уменьшает высоту и ширину вдвое. Параметров у pooling нет.

### Пример: CNN для цифр 28×28

```python
model = nn.Sequential(
    nn.Conv2d(1, 16, kernel_size=3, padding=1),  # (N,1,28,28) -> (N,16,28,28)
    nn.ReLU(),
    nn.MaxPool2d(2),                             # -> (N,16,14,14)

    nn.Conv2d(16, 32, kernel_size=3, padding=1), # -> (N,32,14,14)
    nn.ReLU(),
    nn.MaxPool2d(2),                             # -> (N,32,7,7)

    nn.Flatten(),                                # -> (N, 32·7·7 = 1568)
    nn.Linear(1568, 10)                          # 10 классов, без Softmax
)
```

Параметры: `160 + 4640 + 15 690 = 20 490`. Это намного меньше, чем у MLP `784 → 128 → 10` (около 101 тысячи), а качество на картинках обычно выше.

### Общая структура CNN

```
Изображение → [Conv → ReLU → Pool] × k → Flatten → Linear → выход
              извлечение признаков          классификатор
```

Чем глубже слой, тем более сложные паттерны он видит: границы → текстуры → части объектов → объекты. Область входа, влияющая на один нейрон, называется **рецептивным полем**, и с глубиной оно растёт.

## 23. Рекуррентные сети (RNN, LSTM, GRU)

### Зачем нужны

Для данных-**последовательностей** (текст, звук, временные ряды) важен порядок, а длина бывает разной. MLP принимает вход фиксированного размера и порядок не учитывает.

### Простая RNN

Сеть идёт по последовательности шаг за шагом и хранит **скрытое состояние** `h` («память»):

```
h_t = tanh( W_x · x_t + W_h · h_{t−1} + b )
```

Одни и те же веса применяются на каждом шаге. Обучение идёт через развёртку по времени (backpropagation through time).

Проблема: градиент проходит через много шагов, поэтому затухает или взрывается (раздел 18). Простая RNN плохо помнит далёкое прошлое.

### LSTM и GRU

- **LSTM** добавляет **ячейку памяти** и три «вентиля» (gates): забывания, входа и выхода. Они управляют тем, что стереть, что записать и что выдать. Градиент по ячейке течёт почти без затухания.
- **GRU** — упрощённая версия с двумя вентилями, быстрее и с меньшим числом параметров, качество часто сопоставимо.

### В PyTorch

Форма входа при `batch_first=True`: `(N, T, input_size)`, где `T` — длина последовательности.

```python
class LSTMClassifier(nn.Module):
    def __init__(self, input_size, hidden, n_classes):
        super().__init__()
        self.lstm = nn.LSTM(input_size, hidden, batch_first=True)
        self.fc = nn.Linear(hidden, n_classes)

    def forward(self, x):                 # x: (N, T, input_size)
        _, (h_n, _) = self.lstm(x)        # h_n: (num_layers, N, hidden)
        return self.fc(h_n[-1])           # логиты: (N, n_classes)
```

Что возвращает `nn.LSTM`: `output` формы `(N, T, hidden)` (состояние на каждом шаге) и `(h_n, c_n)` — последнее скрытое состояние и состояние ячейки.

### Ограничения

RNN обрабатывают шаги **по очереди**, их трудно распараллелить, а очень длинные зависимости всё равно даются тяжело. Поэтому для текста их во многом вытеснили трансформеры. Для небольших временных рядов LSTM и GRU остаются рабочим выбором.

## 24. Эмбеддинги

Слова, пользователи, товары — это **категории**, а не числа. One-hot кодирование для словаря в 50 000 слов даёт вектор длины 50 000, почти весь из нулей, и не отражает сходство слов.

**Эмбеддинг (embedding)** — обучаемая таблица, которая каждому номеру категории ставит в соответствие короткий плотный вектор (например, длины 64). Близкие по смыслу объекты в процессе обучения получают близкие векторы.

```python
emb = nn.Embedding(num_embeddings=10000, embedding_dim=64)

ids = torch.tensor([[1, 5, 7],
                    [2, 0, 9]])   # (N=2, T=3), тип long
vectors = emb(ids)                # (2, 3, 64)
```

- Параметров в слое: `10000 · 64 = 640 000`.
- Вход — **целые индексы** (`long`), а не числа с плавающей точкой.
- `padding_idx=0` помечает индекс-заполнитель для выравнивания коротких последовательностей, его вектор не обучается.

Типичная схема для текста:

```
Токены → индексы → Embedding → LSTM / Transformer → Linear → выход
```

Эмбеддинги можно инициализировать готовыми векторами (Word2Vec, GloVe) или обучать с нуля вместе со всей сетью.

## 25. Transfer learning и fine-tuning

Обучать большую сеть с нуля дорого и требует много данных. **Transfer learning** — берём сеть, уже обученную на большом датасете (например, ImageNet), и приспосабливаем под свою задачу. Ранние слои выучили универсальные признаки (границы, текстуры), они полезны везде.

### Вариант 1: заморозить всё, обучить только новую «голову»

```python
from torchvision import models

model = models.resnet18(weights="DEFAULT")   # предобученные веса

for p in model.parameters():
    p.requires_grad = False                  # замораживаем всё

model.fc = nn.Linear(model.fc.in_features, 5)   # новая голова на 5 классов
                                                # (её параметры обучаемы)

optimizer = optim.Adam(model.fc.parameters(), lr=1e-3)
```

Подходит, когда данных мало и задача похожа на исходную.

### Вариант 2: fine-tuning

Размораживаем часть или все слои и дообучаем с **маленьким** `lr`, чтобы не разрушить выученное. Для разных частей сети можно задать разный `lr`:

```python
optimizer = optim.Adam([
    {"params": model.layer4.parameters(), "lr": 1e-4},   # верхний блок: осторожно
    {"params": model.fc.parameters(),     "lr": 1e-3},   # новая голова: смелее
])
```

### Что выбрать

| Данных | Задача похожа на исходную | Подход |
|---|---|---|
| мало | да | заморозить, учить только голову |
| мало | нет | дообучить верхние слои, осторожно |
| много | да | fine-tuning всей сети с малым `lr` |
| много | нет | fine-tuning или обучение с нуля |

> Входные данные должны быть подготовлены так же, как при обучении исходной сети (размер картинки, нормализация). Это указано в документации модели.

## 26. Автоэнкодеры и генеративные модели

До сих пор мы предсказывали `y` по `X`. Здесь учимся **без меток**.

### Автоэнкодер

Сеть из двух частей: **энкодер** сжимает вход в короткий вектор (**латентное представление**, bottleneck), **декодер** пытается восстановить вход из него. Потери — разница между входом и восстановлением.

```
x → [Encoder] → z (малая размерность) → [Decoder] → x̂      loss = MSE(x̂, x)
```

```python
class AutoEncoder(nn.Module):
    def __init__(self, in_dim=784, latent=16):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Linear(in_dim, 128), nn.ReLU(),
            nn.Linear(128, latent)
        )
        self.decoder = nn.Sequential(
            nn.Linear(latent, 128), nn.ReLU(),
            nn.Linear(128, in_dim)
        )

    def forward(self, x):
        return self.decoder(self.encoder(x))

# обучение: criterion(model(x), x) — метки не нужны
```

Применения: сжатие, удаление шума, поиск аномалий (на необычных объектах ошибка восстановления большая), получение признаков.

### Генеративные модели (обзор)

| Модель | Идея |
|---|---|
| **VAE** (вариационный автоэнкодер) | энкодер выдаёт не точку, а распределение в латентном пространстве; можно сэмплировать новые объекты |
| **GAN** | две сети соревнуются: генератор создаёт подделки, дискриминатор отличает их от настоящих |
| **Диффузионные модели** | учатся убирать шум; генерация идёт пошаговым «очищением» случайного шума |
| **Авторегрессионные модели** (языковые модели) | предсказывают следующий элемент последовательности по предыдущим |

## 27. AdamW и gradient clipping

### AdamW

В обычном Adam `weight_decay` смешивается с градиентом и работает не совсем так, как задумано. **AdamW** применяет затухание весов отдельно, и это стандарт для трансформеров.

```python
optimizer = optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)
```

### Gradient clipping

Ограничивает норму градиента и защищает от взрыва. Вставляется **между `backward()` и `step()`**:

```python
optimizer.zero_grad()
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

Особенно полезен для RNN и трансформеров.

## 28. Кросс-валидация, смещение и разброс

### Кросс-валидация (k-fold)

Одно разбиение на train / val может быть удачным или неудачным случайно. Особенно это заметно, когда данных мало. **K-fold**: данные делятся на `k` частей, модель `k` раз обучается, и каждый раз одна из частей служит валидацией. Результаты усредняют.

```
Fold 1: [VAL][train][train][train][train]
Fold 2: [train][VAL][train][train][train]
Fold 3: [train][train][VAL][train][train]
...
```

```python
from sklearn.model_selection import KFold
# для классификации лучше StratifiedKFold: сохраняет доли классов

kf = KFold(n_splits=5, shuffle=True, random_state=42)
scores = []

for train_idx, val_idx in kf.split(X):
    model = build_model()                       # новая модель на каждый фолд!
    # ... обучение на X[train_idx], y[train_idx] ...
    # ... оценка на X[val_idx], y[val_idx], результат добавить в scores ...

print(sum(scores) / len(scores))
```

Для нейросетей на больших данных кросс-валидация дорога, там обычно хватает одного разбиения.

### Смещение и разброс (bias–variance)

Ошибку модели на новых данных можно разложить на части:

- **Смещение (bias)** — ошибка из-за слишком простой модели, которая не способна уловить закономерность. Ведёт к **недообучению**.
- **Разброс (variance)** — чувствительность к конкретной обучающей выборке: модель подгоняется под шум. Ведёт к **переобучению**.
- **Шум** — неустранимая случайность в самих данных.

```
Ошибка
  │\                         /
  │ \     общая ошибка     _/
  │  \                   _/
  │   \_______________ _/       ← оптимум по сложности модели
  │    \  смещение    /  разброс
  └───────────────────────────► сложность модели
```

Усложняем модель: смещение падает, разброс растёт. Задача — найти баланс. Больше данных и регуляризация снижают разброс, более выразительная модель снижает смещение.

## 29. Как выбирать архитектуру

| Данные | Задача | Начать с |
|---|---|---|
| Таблица (числа, категории) | регрессия, классификация | MLP (иногда градиентный бустинг работает на таблицах лучше) |
| Изображения | классификация, детекция | CNN, лучше предобученная (ResNet и др.) |
| Текст | классификация, перевод, генерация | предобученный трансформер |
| Временной ряд | прогноз, классификация | LSTM / GRU, 1D-CNN, трансформер |
| Данных мало, есть похожая готовая модель | любая | transfer learning |
| Меток нет | сжатие, аномалии, генерация | автоэнкодер и другие генеративные модели |

Общий порядок работы над задачей:

1. Понять данные и выбрать метрику, которая соответствует цели.
2. Сделать простую базовую модель (baseline) и записать её результат.
3. Убедиться, что модель способна переобучиться на маленькой выборке (проверка кода).
4. Постепенно усложнять модель, смотреть кривые train / val.
5. Бороться с переобучением регуляризацией, данными, ранней остановкой.
6. Подобрать гиперпараметры, **один раз** оценить на test.
